## 1. Resumen ejecutivo

Codebase **sólido y bien estructurado** en ambos repos. El backend tiene multi-tenancy RLS
ejemplar, secretos cifrados y mypy strict; el frontend está bien tipado (TS strict) y organizado
feature-based con React Query. **No hay hallazgos de seguridad críticos confirmados.**

Los 3 problemas más graves (reales, verificados):

1. **[Alto] Cobertura de tests cero en módulos críticos de seguridad**: `secret_crypto.py` (Fernet)
   y `uploads_storage.py` (I/O) no tienen un solo test. El audit worker solo prueba el happy-path
   con el LLM mockeado. → Fase D.
2. **[Alto] Frontend sin infraestructura de tests**: 0 archivos de test, sin runner. Refactorizar
   los componentes de +480 líneas es riesgoso sin red de seguridad. → Fase D.
3. **[Medio] Drift doc↔código**: los CLAUDE.md describían workers/SSE/webhooks inexistentes y el
   front "stripped to public site" cuando el dashboard ya volvió. **Ya corregido** en esta sesión.

**Veredicto honesto:** no es un codebase con deuda peligrosa. Es un MVP maduro con dos huecos
reales (tests de seguridad backend, infra de tests frontend) y limpieza cosmética pendiente
(mock data, componentes grandes, naming menor). Nada bloquea, pero los tests de `secret_crypto`
y `uploads_storage` deberían existir **antes** de tocar esos módulos.

### Falso positivo descartado

El explorador de frontend reportó como **CRÍTICO** que `.env.local` está versionado en git.
**Es falso** — `git ls-files` no muestra ningún `.env` trackeado en ninguno de los dos repos y
`.gitignore` cubre `.env*.local` y `.env`. Verificado a mano. Se elimina.

### 2.2 Seguridad — **sólido**

| Severidad | Hallazgo | Evidencia |
|-----------|----------|-----------|
| — (OK) | RLS vía `set_config(..., true)` con bound params; cero filas sin tenant | `core/db.py:59-88` |
| — (OK) | API keys de proveedor cifradas Fernet, nunca en claro (masked en UI) | `services/secret_crypto.py`, `routers/settings.py:64` |
| — (OK) | Sin secretos hardcodeados; `.env` no versionado; `jwt_secret` débil rechazado fuera de dev | `core/config.py:51`, `main.py:30` |
| Bajo (info) | JWT: HS256 (secret) primero, JWKS (RS256) como fallback | `core/auth.py:105-113` |

   → ¿se persisten parciales o se rollbackea todo? Hoy solo se prueba happy-path mockeado
   (`tests/test_audit_worker.py`).
3. **[Alto]** `settings` endpoint: provider inválido → 404, key < 8 chars → 422, key inválida →
   `configured=False`.
4. **[Alto]** `uploads_storage`: permiso denegado / path inválido.
5. **[Medio]** `dashboard` e `improvements`: cobertura de endpoint + caso lista vacía + cross-tenant.
6. **[Medio]** web: setup Vitest + RTL; tracer-bullet sobre `lib/api.ts` (ApiError, token attach).
